## create

```rust
use whatsapp_rust::{EventCreationParams, EventResponseType};
let params = EventCreationParams::builder()
    .name("Team offsite".into())
    .description("Bring a laptop".into())
    .build();
let created = client.events().create(&chat, params).await?;
let sent = created.send_result();
println!("{}", sent.message_id);
client.events().respond(&created.event_ref()?, EventResponseType::Going, Some(2)).await?;
```

`create` returns `Result<CreatedEvent, SendError>`. `CreatedEvent` carries the original `SendResult`, cryptographic creator `Jid`, and validated 32-byte `MessageSecret`. Read them with `send_result()`, `creator()`, and `secret()`. `event_ref()` borrows the association without cloning the protobuf. `into_parts()` transfers ownership explicitly.

## EventCreationParams

Use `EventCreationParams::builder()` with a required `name`. Optional fields are `description`, `start_time`, `end_time`, `join_link`, `location`, `is_scheduled_call`, and `extra_guests_allowed`. Times are Unix seconds. Blank names fail before send. The extensible DTO has no invalid all-default constructor; add `..` in patterns.

## respond

`respond(&EventRef, EventResponseType, Option<i32>)` sends an encrypted RSVP and returns its `SendResult`. `Going`, `NotGoing`, and `Maybe` are response choices. The creator must be the original crypto identity, not an assumed current PN/LID alias.

For received or stored events, construct `EventRef::new(message_ref, &creator, &secret)?`. The host must associate matching addressing, creator, and secret; construction validates shape without proving that association. `respond_raw` is the explicit string/slice interop path and validates IDs and secret length before encryption.

## Secrets and inbound responses

`MessageSecret` accepts exactly 32 bytes, redacts `Debug`, and zeroizes owned bytes on drop. `CreatedEvent` and `EventRef` redact their debug output too. Explicitly exposing `SendResult` or its protobuf can expose the embedded secret; do not log those values as if redaction still applied.

Use `wacore::event::decrypt_event_response_with_secret` for inbound encrypted RSVP data, with the stored original ID, creator, and responder identities. The library's receive path materializes supported encrypted add-ons. See [message references](/api/send#message-references-and-ids) and [poll secrets](/api/polls#creation-references).
