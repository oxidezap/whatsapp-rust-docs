## Overview

`waproto` provides generated Rust types and codecs for WhatsApp's Protocol Buffers. The crate owns the public protobuf runtime and generates its models from the committed descriptor during the build.

```toml
[dependencies]
waproto = "0.7"
```

## Structure

```
waproto/
├── src/
│   ├── lib.rs               # Module definition + tags re-export
│   ├── whatsapp.proto       # Source protobuf definitions
│   ├── whatsapp.desc        # Binary FileDescriptorSet (committed)
│   └── whatsapp.desc.sha256 # SHA-256 of descriptor and proto
└── build.rs                 # Generates the model and tags in OUT_DIR
```

The build writes the model and field tags to `OUT_DIR`. Consumers do not need `protoc`. Contributors need it to regenerate the committed descriptor.

## Usage

All protobuf types are under the `waproto::whatsapp` module:

```rust
use waproto::whatsapp as wa;

let mut message = wa::Message::default();
message.conversation = Some("Hello, World!".to_string());
```

Sub-message fields use `waproto::protobuf::MessageField<T>`. Construct one with `MessageField::some(..)` and read it with `.as_option()`, `.is_set()`, or `.is_unset()`.

<Note>
  The SDK re-exports this module as `whatsapp_rust::protobuf` and exposes `MessageField` in the prelude. The historical `waproto::buffa` and `whatsapp_rust::buffa` paths refer to the same project-owned module. If your code uses traits from the external `buffa` crate, import the corresponding traits from `waproto::protobuf` for generated WhatsApp types.
</Note>

```rust
use waproto::protobuf::MessageField;
use waproto::whatsapp as wa;

let mut image = wa::message::ImageMessage::default();
image.caption = Some("Check this out!".to_string());
let mut img = wa::Message::default();
img.image_message = MessageField::some(image);

if let Some(image) = img.image_message.as_option() {
    println!("caption: {:?}", image.caption);
}
```

Optional scalar and enum fields use `Option<T>`. Required fields use their value type. Generated messages and enums are non-exhaustive, so construct messages with `Default` and field assignments, and include a fallback when matching enums.

Import `Message` to encode or decode owned values. Import `MessageView` to decode a view that borrows strings and bytes from the input buffer.

```rust
use waproto::protobuf::{Message as _, MessageView as _};
use waproto::whatsapp as wa;

fn main() -> Result<(), waproto::protobuf::DecodeError> {
    let mut message = wa::Message::default();
    message.conversation = Some("Hello".into());
    let encoded = message.encode_to_vec();
    let view = wa::MessageView::decode_view(&encoded)?;
    assert_eq!(view.conversation, Some("Hello"));
    Ok(())
}
```

Views expose `has_*` methods for required fields. For example, `ConversationView::has_id()` distinguishes an absent ID from an explicitly encoded empty ID. The default view reports required scalar fields as absent.

Decoders discard unknown fields and limit how many they skip across a message tree. Use `DecodeOptions::with_unknown_field_limit` to set that limit. Preserve the original bytes when forwarding fields outside the current schema.

## Enums

waproto generates real Rust enums (not raw `i32` constants). Variant names are `SCREAMING_SNAKE_CASE`:

```rust
// Message types
pub mod protocol_message {
    pub enum Type {
        REVOKE = 0,
        EPHEMERAL_SETTING = 3,
        EPHEMERAL_SYNC_RESPONSE = 4,
        HISTORY_SYNC_NOTIFICATION = 5,
        APP_STATE_SYNC_KEY_SHARE = 6,
        APP_STATE_SYNC_KEY_REQUEST = 7,
        MESSAGE_EDIT = 14,
        // ...
    }
}

// Media types
pub mod video_message {
    pub enum Attribution {
        NONE = 0,
        GIPHY = 1,
        TENOR = 2,
    }
}
```

<Note>
Most generated enum fields are closed. An unrecognized wire value is discarded. `SyncdMutation.operation` and the status privacy distribution mode use the open `waproto::protobuf::EnumValue<T>` representation, which retains unknown integer values. App-state processing rejects an unknown sync operation before changing state.
</Note>

## Feature flags

| Feature | Description | Implies |
|---|---|---|
| `serde-deserialize` | Adds `#[derive(serde::Deserialize)]` and `#[serde(default)]` to all types. Use when you need to parse protobuf types from JSON. | — |
| `serde-snake-case` | Accepts snake_case enum variant names during deserialization. Serialize output is unchanged. | `serde-deserialize` |
| `serde-enum-repr` | Enums (de)serialize as their numeric repr instead of the variant name — what the JS/WASM bridge and camelCase serializer expect. | — |

<Note>
The `generate` feature was removed in [#836](https://github.com/oxidezap/whatsapp-rust/pull/836). Normal builds generate the model automatically.
</Note>

## Serde support

All generated types derive `serde::Serialize` by default. Deserialization and snake_case renaming are behind optional feature flags (`serde-deserialize` and `serde-snake-case` above).

Enable them in your `Cargo.toml`:

```toml
[dependencies]
waproto = { version = "0.7", features = ["serde-snake-case"] }
```

### Default behavior (no feature flags)

All types derive `Serialize` only:

```rust
#[derive(Clone, PartialEq, Default)]
#[derive(serde::Serialize)]
pub struct Message {
    // ...
}
```

This allows JSON serialization for debugging:

```rust
let json = serde_json::to_string_pretty(&message)?;
println!("Message: {}", json);
```

### With `serde-deserialize`

All types also derive `Deserialize` with `#[serde(default)]`, matching protobuf semantics where missing fields use default values:

```rust
#[derive(serde::Serialize)]
#[cfg_attr(feature = "serde-deserialize", derive(serde::Deserialize))]
#[cfg_attr(feature = "serde-deserialize", serde(default))]
pub struct Message {
    // ...
}
```

### With `serde-snake-case`

All types additionally accept snake_case during deserialization. This primarily affects enum and oneof variants, while struct fields are already snake_case. Serialization output remains unchanged.

```rust
// Without serde-snake-case: must use SCREAMING_SNAKE_CASE
let json = r#"{"accountType": "ENTERPRISE"}"#;

// With serde-snake-case: snake_case also accepted
let json = r#"{"account_type": "enterprise"}"#;
```

<Note>
  The `serde-snake-case` feature is primarily useful for WASM bridge scenarios where JavaScript sends snake_case JSON to the Rust backend. For most Rust-only use cases, you only need the default `Serialize` support.
</Note>

## waproto::tags

The build generates the `waproto::tags` module from the compiled protobuf descriptor. You get one `pub mod` per proto message with one `pub const FIELD_NAME: u32 = N;` per field. Nested messages produce nested modules.

```rust
use waproto::tags;

// Field numbers derived directly from whatsapp.proto
let _ = tags::web_message_info::KEY;           // 1
let _ = tags::web_message_info::MESSAGE;       // 2
let _ = tags::message::MESSAGE_CONTEXT_INFO;   // 35
let _ = tags::history_sync::CONVERSATIONS;     // 2
let _ = tags::history_sync::PUSHNAMES;         // 7
```

The history-sync wire walkers use these constants internally, and compile-time `assert!` blocks pin them in the hand-written mirror structs. If `whatsapp.proto` renumbers a field the consts update automatically on next build; if a field referenced by the walkers is renamed or removed, compilation fails rather than the decoder silently reading the wrong wire data.

## Code generation

The build script verifies the committed descriptor and generates the owned types, borrowed views and `waproto::tags` constants in `OUT_DIR`. The repository-owned generator keeps protobuf field names in the source schema and emits Rust identifiers in snake_case. Normal builds do not invoke `protoc`.

**To update after modifying `whatsapp.proto`:**

```bash
cargo xt proto-desc
cargo xt proto-codecs --check
```

The build aborts with a clear message if the descriptor SHA-256 does not match.

<Note>
The `generate` feature flag was removed. Code generation is now always-on and does not require any feature flags. Remove `--features generate` from any existing build scripts.
</Note>

### Constructing Messages

```rust
use waproto::protobuf::MessageField;
use waproto::whatsapp as wa;

// Text message
let mut text = wa::Message::default();
text.conversation = Some("Hello!".to_string());

// Image with caption
let mut image_content = wa::message::ImageMessage::default();
image_content.url = Some(media_url);
image_content.media_key = Some(media_key.to_vec());
image_content.file_sha256 = Some(file_sha256.to_vec());
image_content.file_enc_sha256 = Some(file_enc_sha256.to_vec());
image_content.caption = Some("Nice photo!".to_string());
image_content.jpeg_thumbnail = Some(thumbnail);
let mut image = wa::Message::default();
image.image_message = MessageField::some(image_content);

// Quoted reply
let mut context = wa::ContextInfo::default();
context.stanza_id = Some(original_message_id);
context.participant = Some(original_sender);
context.quoted_message = MessageField::some(original_message);

reply.extended_text_message = MessageField::some(content);
```

### Pattern Matching

`MessageField` doesn't pattern-match like `Option` directly — match on `.as_option()` instead:

```rust
match (&proto_msg.conversation, proto_msg.image_message.as_option(), proto_msg.video_message.as_option()) {
    (Some(text), _, _) => {
        println!("Text: {}", text);
    }
    (_, Some(img), _) => {
        println!("Image from: {}", img.url.as_deref().unwrap_or_default());
    }
    (_, _, Some(vid)) => {
        println!("Video: {} seconds", vid.seconds.unwrap_or(0));
    }
    _ => println!("Other message type"),
}
```

## Relationship with wacore

wacore provides utilities for working with waproto messages:

- **`proto_helpers`** - Conversion between protobuf and internal types
- **`download`** - `Downloadable` trait for media messages
- **`upload`** - Media encryption for upload
- **`messages`** - Message encryption/decryption
- **`send`** - Message building and sending

Example:

```rust
use waproto::protobuf::MessageField;
use waproto::whatsapp as wa;

let mut key = wa::MessageKey::default();
key.remote_jid = Some("12345@s.whatsapp.net".into());
key.id = Some("example-message-id".into());
key.from_me = Some(true);
let mut protocol = wa::message::ProtocolMessage::default();
protocol.key = MessageField::some(key);
protocol.r#type = Some(wa::message::protocol_message::Type::REVOKE);
let mut revoke = wa::Message::default();
revoke.protocol_message = MessageField::some(protocol);
```
