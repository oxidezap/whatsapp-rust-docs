The `Profile` feature provides methods for managing your own account's display name, status text (about), and profile picture.

## Access

Access profile operations through the client:

```rust
let profile = client.profile();
```

## Methods

### set_push_name

`set_push_name(&str)` returns `Result<PushNameOutcome, ProfileError>`. An empty name is rejected. A presence transport failure returns an error before changing the local name. Otherwise, the client attempts app-state synchronization and updates the local name.

`Synced` means the app-state step completed. `SyncPending { source }` retains the original `AppStateError` after presence was sent and the local name updated. Neither outcome proves that every linked device displays the name or that all local state is durable. Transport acceptance is not a server ACK.

```rust
use whatsapp_rust::{Client, ProfileError, PushNameOutcome};

async fn set_name(client: &Client, name: &str) -> Result<PushNameOutcome, ProfileError> {
    let outcome = client.profile().set_push_name(name).await?;
    match &outcome {
        PushNameOutcome::Synced => println!("Push-name synchronization completed"),
        PushNameOutcome::SyncPending { source } => {
            eprintln!("Push-name synchronization pending: {source}");
        }
        _ => {}
    }
    Ok(outcome)
}
```

Retain the desired name with a pending outcome so your retry policy can act on its cause. Pending synchronization is possible during pairing before app-state keys arrive.

### sync_push_name

`sync_push_name(&str)` returns `Result<(), AppStateError>`. Retry this step after the connection or keys become available. It sends only the app-state mutation, without resending presence or changing the local name. Retry only if the pending name is still desired; do not overwrite a newer choice.

```rust
use whatsapp_rust::{Client, AppStateError};

async fn retry_name_sync(client: &Client, pending_name: &str) -> Result<(), AppStateError> {
    client.profile().sync_push_name(pending_name).await
}
```

### set_status_text

Set your status text (about).

```rust
pub async fn set_status_text(&self, text: &str) -> Result<(), ProfileError>
```

**Parameters:**
- `text` - The new status text

Sets the profile "About" text. This is different from ephemeral text status updates.

**Example:**
```rust
client.profile().set_status_text("Available 24/7").await?;
```

### set_profile_picture

Set your profile picture.

```rust
pub async fn set_profile_picture(
    &self,
    image_data: Vec<u8>
) -> Result<SetProfilePictureResponse, ProfileError>
```

**Parameters:**
- `image_data` - JPEG image bytes

**Returns:**
- `SetProfilePictureResponse` - Contains the new picture ID

The image should already be properly sized/cropped by the caller. WhatsApp typically uses 640x640 images.

**Example:**
```rust
use std::fs;

let image_bytes = fs::read("profile.jpg")?;
let response = client.profile().set_profile_picture(image_bytes).await?;
println!("New picture ID: {:?}", response.id);
```

<Warning>
The image must be a valid JPEG. Other formats are not supported.
</Warning>

### remove_profile_picture

Remove your profile picture.

```rust
pub async fn remove_profile_picture(&self) -> Result<SetProfilePictureResponse, ProfileError>
```

**Returns:**
- `SetProfilePictureResponse` - Confirmation of removal

**Example:**
```rust
client.profile().remove_profile_picture().await?;
```

<Note>
Since v0.6 the remove IQ omits the `<picture/>` child entirely, matching WA Web's `SendProfilePictureJob`. Sending an empty `<picture>` child was rejected by some hosts.
</Note>

## Retain pending synchronization

The `set_name` helper above returns the outcome to its caller. Store the pending name and cause before starting unrelated profile operations, so a later picture or status-text failure cannot discard the synchronization result.

## Error handling

Profile updates return `Result<T, ProfileError>`; the app-state-only retry returns `Result<(), AppStateError>`:

```rust
#[derive(Debug, thiserror::Error)]
#[non_exhaustive]
pub enum ProfileError {
    #[error("{0}")]
    Iq(#[from] IqError),
    #[error("{0}")]
    Client(#[from] ClientError),
    #[error("invalid argument: {0}")]
    InvalidArgument(String),
    #[error("{0}")]
    Internal(#[from] anyhow::Error),
}
```

Common errors:
- `InvalidArgument` — e.g., empty push name
- `Iq` — server rejected the status text or picture IQ
- `Client(ClientError::NotLoggedIn)` — not authenticated
- `Internal` — network errors, encoding failures

```rust
use whatsapp_rust::ProfileError;

match client.profile().set_push_name("").await {
    Ok(outcome) => println!("Inspect name outcome: {outcome:?}"),
    Err(ProfileError::InvalidArgument(msg)) => eprintln!("Invalid: {}", msg),
    Err(e) => eprintln!("Failed: {}", e),
}
```
