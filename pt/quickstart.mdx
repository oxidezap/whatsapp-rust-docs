Use a dependência indicada em [Instalação](/pt/installation). O crate principal reexporta os componentes usados neste exemplo.

```rust src/main.rs
use whatsapp_rust::prelude::*;

#[tokio::main]
async fn main() -> Result<(), Box<dyn std::error::Error>> {
    let bot = Bot::builder()
        .with_backend(SqliteStore::open("whatsapp.db").await?)
        .on_qr_code(|code, _timeout| async move {
            println!("Leia este QR code com o WhatsApp:\n{code}");
        })
        .on_message(|ctx| async move {
            if ctx.message.text_content() == Some("ping") {
                if let Err(error) = ctx.reply("pong").await {
                    eprintln!("Falha ao responder: {error}");
                }
            }
        })
        .build()
        .await?;

    let reason = bot.run().await;
    println!("Sessão encerrada: {reason:?}");
    Ok(())
}
```

`SqliteStore::open` mantém a sessão entre execuções. As features padrão fornecem runtime Tokio, transporte WebSocket e cliente HTTP; escolha o backend explicitamente.

`on_message` recebe `MessageContext`, com a mensagem, seus metadados e métodos como `reply`, `reply_quoting`, `react` e `send_message`. Os callbacks usam filas e concorrência limitadas por padrão. `EventDelivery::Ordered` executa em sequência os callbacks dos eventos aceitos na fila, na ordem de enfileiramento. Isso não garante ordem global, ordem por timestamp nem entrega de eventos descartados por overflow ou cancelamento; retenha dados em armazenamento próprio se precisar de processamento durável.

`bot.run().await` executa a sessão no chamador e retorna `RunCompletionReason`. `bot.spawn()` executa em background e retorna um handle cujo resultado distingue conclusão, pedido de cancelamento e término sem resultado observado. Encerre pelo `Client::shutdown()` e confira o relatório de persistência; o fechamento do socket, sozinho, não confirma que os dados foram gravados.

Use `client.send(SendRequest)` quando precisar de opções. Para editar ou reagir, obtenha `MessageRef` da mensagem recebida ou de `SendResult::message_ref()` e use os métodos tipados. Para ações em canais, use `NewsletterMessageRef`; reações precisam do `ServerMessageId` observado no servidor, que não pode ser inferido do ID local do envio. `MessageId` identifica conteúdo, `StanzaId` identifica operações e `ServerMessageId` identifica conteúdo observado de canais; preserve essas funções.

Para construir protobufs diretamente, use `Default` e atribua os campos. Ao modificar uma mensagem existente, use `clone()` antes de alterar os campos necessários.

```rust
let mut message = wa::Message::default();
message.conversation = Some("Olá!".to_string());
```
