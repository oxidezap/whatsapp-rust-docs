## Send text or protobuf content

```rust
use whatsapp_rust::{Client, Jid};
use whatsapp_rust::proto_helpers::MessageBuilderExt;
use whatsapp_rust::waproto::whatsapp::Message;

async fn send(client: &Client, chat: &Jid) -> whatsapp_rust::anyhow::Result<()> {
    client.send_text(chat, "Hello").await?;
    let sent = client.send_message(chat, Message::text("Next message")).await?;
    client.send_reaction(&sent.message_ref()?, "👍").await?;
    Ok(())
}
```

For media, quotes, business content and other protobuf shapes, prepare the message and send it through the same pipeline. Follow [media](/guides/media-handling), [business messages](/api/business) and [protobuf construction](/api/waproto) for their content builders.

## Set options once

Wrap the message in `SendRequest::new(chat, message).with_options(options)` and call `client.send(request).await`. Build `SendOptions` from `Default`; typed IDs and `with_*` setters replace old literals and option overloads. The [send task reference](/api/send#send) includes a complete example.

For disappearing content, use the chat's chosen expiration. A per-message option does not change the chat timer. For an explicit fresh device query after `NoRecipientDevice`, set device freshness on the next request.

## Preserve the original target

Use `message_ref()` on the received message, context or send result. Pass that reference to reactions, revokes, pins and keeps. Build `EditRequest` for edits. A target includes its original author and origin metadata, so rebuilding it from an ID alone can lose routing context.

Keep the original content ID separate from an operation's returned ID. A reaction or edit is a new stanza, and its ACK is not an ACK for the target content or proof of recipient delivery.

## Forward without copying a secret

Use `forward_message` for default sends. Use `prepare_for_forward` followed by a `SendRequest` to customize the result. Preparation drops the source's secret and quote chain and sets forwarding metadata; do not attach the original secret back to forwarded content.

```rust
use whatsapp_rust::{Client, Jid, SendOptions, SendRequest};
use whatsapp_rust::proto_helpers::MessageExt;
use whatsapp_rust::waproto::whatsapp::Message;
use whatsapp_rust::wacore_binary::node::Node;

async fn forward_with_options(
    client: &Client,
    destination: &Jid,
    original: &Message,
    extra_nodes: Vec<Node>,
) -> whatsapp_rust::anyhow::Result<()> {
    let options = SendOptions::default().with_extra_stanza_nodes(extra_nodes);
    client.send(
        SendRequest::new(destination, original.prepare_for_forward())
            .with_options(options),
    ).await?;
    Ok(())
}
```

## Address specialized content

- [Polls](/api/polls) and [events](/api/events) return named creation results carrying their parent crypto association.
- [Status](/api/status) posts need an explicit audience and different ID options for content and operations.
- [Newsletter actions](/api/newsletter) use `NewsletterMessageRef` because channel client IDs and server content IDs are separate domains.
- [Community announcement posts](/guides/communities) need the original author and secret for encrypted edits and comments.

For exact signatures, use the pinned source links in [the send reference](/api/send); for released crates, select that release's Rustdoc. The [current API guide](/guides/current-api) explains request construction and ID boundaries.

## Album messages

Send an `AlbumMessage` parent declaring the image/video counts, then link each prepared media message using `wrap_as_album_child`. Children are separate sends; cancelling midway does not roll back the parent or earlier children.

```rust
use whatsapp_rust::{Client, Jid, buffa, waproto::whatsapp as wa};
use whatsapp_rust::proto_helpers::wrap_as_album_child;

async fn album(client: &Client, chat: &Jid, images: Vec<wa::Message>) -> whatsapp_rust::anyhow::Result<()> {
    let parent = wa::Message {
        album_message: buffa::MessageField::some(wa::message::AlbumMessage {
            expected_image_count: Some(images.len().try_into()?),
            expected_video_count: Some(0),
            ..Default::default()
        }),
        ..Default::default()
    };
    let sent = client.send_message(chat, parent).await?;
    for image in images {
        client.send_message(chat, wrap_as_album_child(image, sent.message_key())).await?;
    }
    Ok(())
}
```

## Sticker packs

Prepare 512×512 WebP stickers and a cover with `wacore::sticker_pack::create_sticker_pack_zip`. Upload the ZIP as `MediaType::StickerPack`, then the JPEG thumbnail as `StickerPackThumbnail` with the ZIP upload's same media key. Build the content with `build_sticker_pack_message` and send it through the ordinary pipeline. Uploading and sending are separate operations.

See [media handling](/guides/media-handling) and the pinned core helper for exact metadata and upload projections.

## Quoted replies

Use `MessageContext::reply_quoting` to include quote context from the incoming message. For manual protobuf assembly, its `build_quote_context()` exposes the quoted association. Sending, editing or forwarding content does not implicitly quote an arbitrary previous message.
